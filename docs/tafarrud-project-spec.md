# مشروع «تَفرّد» — الوثيقة النهائية

متجر إلكتروني لحقائب جاهزة وحقائب مخصصة. يختار العميل موديلاً أساسياً أبيض، ثم الخامة واللون والتطريز، فيُولَّد له بالذكاء الاصطناعي صورة للتصميم (وجه أمامي وخلفي في صورة واحدة)، ثم يدفع ويتابع طلبه.

---

## 1. الفكرة والفئات المستهدفة

**الفكرة:** تجربة شراء تشاركية: العميل يشارك في تصميم حقيبته ويرى نتيجة قبل التصنيع.

**الفئات المستهدفة:**

- الموظفات (شنط يد)
- الطالبات (باوتش وتوت باق)
- المهتمات بالتصميم

**نوعا المنتجات في المتجر:**

- **جاهز:** شراء مباشر بسعر ثابت ومخزون.
- **مخصص:** شنطة بيضاء أساسية + خيارات + صورة مولّدة، بدون مخزون وبمدة تنفيذ (مثلاً 7-10 أيام).

**الأنواع الثلاثة:** شنطة يد، توت باق، باوتش — بحجمين: صغير (20×15×7 سم) وكبير (40×30×15 سم).

---

## 2. نتائج الاستبيان (319 رداً)

| السؤال | النتيجة |
| --- | --- |
| النوع المفضل | شنطة يد 52.7%، توت باق 24.1%، باوتش 23.2% |
| الحجم | صغير 70.5%، كبير 29.5% |
| سعر الصغير | أقل من 150: 49.8%، 150-250: 47%، أعلى من 250: نحو 3% |
| سعر الكبير | 250-300: 64.6%، 300-350: 30.1%، أعلى من 350: نحو 5% |
| الشراء سنوياً | 2-3 مرات 51.7%، مرة واحدة 45.8%، 4-5 مرات نحو 2.5% |
| الخامة المستدامة | جلد نباتي 48.3%، قطن عضوي 21.6%، سدو تراثي 19.1%، جينز معاد تدويره 11% |
| أهم ما يريدون تخصيصه | الشكل 80.3%، القماش 73%، لون الشنطة 71.2%، الحجم 68%، النقش/التطريز 54.5% |

### قرارات مبنية عليها

1. البداية بالشنط اليدوية الصغيرة، وسعرها المستهدف **120-180 ريال**.
2. الجلد النباتي هو الخامة الافتراضية، والسدو ميزة للتفرّد، والجينز يؤجَّل.
3. الشكل أهم خيار، لذلك **الموديل نفسه هو اختيار الشكل**، ويلزم 3-4 موديلات لكل نوع.
4. التخصيص: الخامة، اللون، الحجم، الاسم/التطريز.
5. الشنطة الكبيرة بسعر 250-300 ريال.

> ملاحظة: الاستبيان يقيس ما يقبل العميل دفعه، لا تكلفة التصنيع. يجب التأكد أن الأسعار تغطي التصنيع وتكلفة توليد الصور.

---

## 3. الأدوار

- **الزائر / العميل:** يتصفح ويصمم ويطلب ويتابع الطلبات.
- **المدير:** مصمم + إدارة في لوحة واحدة، ويُعرَّف بـ Firebase custom claim باسم `admin`.

---

## 4. المعمارية والتقنيات

- **Node 24.17** + **Next.js** (واجهة عربية RTL) + **Tailwind**
- **Supabase:** قاعدة Postgres + Storage للصور
- **Firebase Auth:** بريد وكلمة مرور وGoogle
- **قراءة الكتالوج:** من الواجهة مباشرة (قراءة فقط).
- **كل الكتابة** عبر API في الخادم، وهو:
  1. يتحقق من توكن Firebase (`firebase-admin`)
  2. يحسب السعر
  3. يولّد الصورة
  4. يكتب في Supabase بمفتاح الخدمة (لا يصل للمتصفح أبداً)

---

## 5. الشاشات

### عامة (بدون تسجيل)

1. **الرئيسية:** الفكرة، زر «صمّم شنطتك»، الجاهز، أمثلة
2. **المتجر (الجاهز):** فلتر بالنوع والحجم والسعر
3. **صفحة منتج جاهز:** صور، سعر، أضف للسلة
4. **صمّم شنطتك**
5. **السلة**

### الحساب

6. **دخول / إنشاء حساب**
2. **ملفي:** الاسم، الجوال، المدينة، العنوان

### العميل

8. **نتيجة التصميم:** الصورة (أمامي وخلفي)، المواصفات، السعر النهائي، «أعد التوليد»، «ادفع»
2. **الدفع التجريبي**
3. **طلباتي:** قائمة + تفاصيل بخط زمني للحالة

### المدير
 1. **الطلبات:** فلتر بالحالة
 2. **تفاصيل الطلب:** الصورة، المواصفات، تغيير الحالة، ملاحظة
 3. **المنتجات الجاهزة**
 4. **الموديلات الأساسية:** صور أمام/خلف ومنطقة النص
 5. **الخيارات والأسعار:** خامات، ألوان، إضافات، سقف السعر

## 6. شريط التنقل (Navbar)

| الحالة | المحتوى |
| --- | --- |
| زائر | الشعار، الرئيسية، المتجر، صمّم شنطتك، السلة، **[تسجيل الدخول]**، **[إنشاء حساب]** |
| مسجّل | نفس الروابط، و**[صورة البروفايل]** (قائمة: ملفي، خروج) + **[طلباتي]** |

يتحول زر «تسجيل الدخول» إلى صورة البروفايل، ويتحول «إنشاء حساب» إلى «طلباتي».

---

## 7. صفحة «صمّم شنطتك»

- **أعلى الشاشة:** صورة الشنطة البيضاء الأساسية للموديل المختار.
- **الخطوات:** النوع ← الموديل والحجم ← الخامة ← اللون ← الاسم/التطريز.
- **شريط ثابت أسفل الشاشة:** السعر الحي + زر «أنشئ التصميم».
- التصفح والاختيار متاحان لأي زائر دون تسجيل.

### بوابة تسجيل الدخول

عند الضغط على «أنشئ التصميم» دون تسجيل دخول:

1. تُحفظ الاختيارات في `sessionStorage`.
2. يُحوَّل العميل إلى صفحة الدخول/إنشاء الحساب مع `next=/design`.
3. بعد الدخول يعود ويجد اختياراته كما هي، ويكمل التوليد تلقائياً.

---

## 8. توليد الصورة بالذكاء الاصطناعي

1. **البرومبت** يُبنى من **قالب ثابت** تملؤه الاختيارات، ولا يكتبه العميل. مثال:
   > حقيبة يد صغيرة، جلد نباتي، لون بيج، تصوير منتج على خلفية بيضاء، الوجهان الأمامي والخلفي بنفس الخامة واللون تماماً.
2. **تحرير صورة، لا توليد من الصفر:** تُرسل صورة الشنطة البيضاء مع البرومبت ليبقى الشكل ثابتاً ويتغير اللون والخامة فقط.
3. **وجه أمامي وخلفي في صورة واحدة:**
   - لكل شنطة بيضاء صورتان (أمامية وخلفية) بنفس الزاوية والإضاءة والخلفية.
   - يدمجهما الخادم جنباً إلى جنب قبل الإرسال.
   - يُطلب تعديل الوجهين في طلب واحد لضمان التناسق.
4. **النص العربي لا يكتبه الذكاء الاصطناعي** (يشوّه الحروف):
   - يضيف الخادم الاسم/التطريز **فوق الصورة المولّدة** بخط Cairo أو Tajawal.
   - في إحداثيات ثابتة لكل موديل تحددها في لوحة المدير.
5. **ملاحظة العميل النصية الحرة:** قصيرة ومفلترة، ولا تدخل البرومبت مباشرة.
6. **حد المحاولات:** 3 صور لكل تصميم، مع **Rate Limit** على نقطة التوليد.
7. أسفل الصورة: «الصورة تقريبية، والمنتج النهائي قد يختلف قليلاً».
8. **المرجع الفعلي للتصنيع هو قائمة الاختيارات** (الموديل، الخامة، اللون...) وليس الصورة.

---

## 9. محرك السعر

- يحسبه **الخادم فقط**: السعر الأساسي للموديل + سعر الخامة + سعر الإضافات.
- **السعر النهائي شامل كل شيء** (الشحن مضمّن)، فلا رسوم خفية.
- **سقف الاستبيان:** الصغير حتى 250 ريال، والكبير حتى 350 ريال.
- لوحة المدير ترفض حفظ أي إعداد يمكن أن يتجاوز السقف في `price_limits`.

### مثال للبداية (يعدَّل حسب التكلفة الفعلية)

| البند | الصغير | الكبير |
| --- | --- | --- |
| السعر الأساسي | 120 | 260 |
| جلد نباتي | 0 | 0 |
| قطن عضوي | +10 | +15 |
| سدو | +40 | +50 |
| تطريز اسم | +20 | +25 |

---

## 10. الدفع (تجريبي)

- يقبل أي بيانات، حتى الوهمية.
- لا يُخزَّن رقم البطاقة؛ يكفي `payment_status` وآخر 4 أرقام.
- يكتب الخادم الحالة `paid` مباشرة بعد «الدفع».
- يأتي الدفع **بعد** توليد الصورة، وللمدير زر **رفض مع استرجاع** للحالات الشاذة.

---

## 11. حالات الطلب

```
بانتظار الدفع ← مدفوع (قيد المراجعة) ← مقبول ← قيد التصنيع ← تم الشحن ← تم التسليم
                         ↘ مرفوض / مسترجع
```

كل تغيير يُسجَّل في `order_status_log` ليظهر في الخط الزمني لصفحة «طلباتي».

## 12. قاعدة البيانات (Supabase / Postgres)

| الجدول | أهم الحقول |
| --- | --- |
| `profiles` | `id` (uid من Firebase)، الاسم، الجوال، المدينة، العنوان |
| `bag_types` | شنطة يد، توت باق، باوتش |
| `base_models` | النوع، الاسم، الحجم (صغير/كبير)، السعر الأساسي، صورة أمامية، صورة خلفية، منطقة النص (x, y, w, h) |
| `materials` | الاسم، سعر الصغير، سعر الكبير، `prompt_text` |
| `colors` | الاسم، hex، `prompt_text` |
| `addons` | تطريز اسم/شعار، سعر الصغير، سعر الكبير |
| `price_limits` | الحجم، السقف (250 / 350) |
| `ready_products` | النوع، الحجم، السعر، الصور، المخزون |
| `designs` | المستخدم، الموديل، الخامة، اللون، النص والخط، **البرومبت**، رابط الصورة، السعر، عدد المحاولات |
| `orders` | المستخدم، النوع (جاهز/مخصص)، `design_id`، الإجمالي، الحالة، لقطة العنوان، حالة الدفع |
| `order_items` | الطلب، المنتج الجاهز، الكمية، السعر |
| `order_status_log` | الطلب، الحالة، الملاحظة، الوقت |

## 13. الأمان

- لا يثق الخادم بأي سعر قادم من المتصفح.
- التحقق من توكن Firebase في كل نقطة كتابة.
- مفتاح خدمة Supabase في الخادم فقط.
- Rate Limit على التوليد، ومحاولات محدودة لكل تصميم.
- صلاحيات المدير عبر custom claim فقط.

---

## 14. الموارد المطلوبة

- **صورتان لكل شنطة بيضاء** (أمامية وخلفية) بخلفية موحدة وإضاءة متشابهة: 3 أنواع × 3-4 موديلات.
- **صور المنتجات الجاهزة** مع الأسعار والمخزون.
- **صور عينات** للخامات والألوان (للأزرار).

## 16. خطوات التنفيذ المقترحة

1. تجهيز صور الشنط البيضاء (أمام/خلف) لموديل أو موديلين للتجربة.
2. إنشاء مشروعي Firebase وSupabase، وكتابة SQL الجداول وسياسات القراءة.
3. بناء الكتالوج (المتجر الجاهز) وسلة الشراء.
4. بناء صفحة «صمّم شنطتك» مع محرك السعر.
5. ربط التوليد (تحرير الصور) والتحقق من الدخول وحدّ الاستخدام.
6. إضافة النص العربي فوق الصورة.
7. الدفع التجريبي وصفحة «طلباتي».
8. لوحة المدير.
9. اختبار كامل ثم إطلاق تجريبي.
